# Standalone Vercel webcam preview

Use a dedicated project named `signrelay-v2-lab`. Set its Root Directory to `engine-v2`, use the **Other** framework preset and enable **Include source files outside of the Root Directory in the Build Step**. The lab's own `vercel.json` installs the existing repository lockfile, builds the lab, and publishes `dist-preview`. Use Vercel Authentication with Standard Protection for the preview. Deploy the review branch as a Preview without promoting it.

Run `node engine-v2/build-preview.mjs` from the repository root after `npm ci` to inspect the same static output locally. The build accepts only the pinned V2 landmark file and MediaPipe assets. It downloads missing hand and pose models from the official mirror at build time and checks their size and SHA-256. The published output contains 13 files. The browser fetches all assets from the lab origin and uses the existing hand-tracking and pose workers. Camera frames, landmarks and the trial log stay in the tab. The output policy restricts connections, workers and camera permissions to the lab origin, and disallows embedding.

In Chrome, sign in if prompted, select **Freshness guard (experimental)**, choose **Start camera** and grant access. Wait for **Camera running**. Sign HELLO, THANK YOU, PLEASE, YES and NO one at a time. Watch **Confirmed suggestions** and use **Score webcam trials** to test each word and export anonymous JSON. Stop the camera before switching the recognition policy. Recognition scores are raw model scores.

For a built-output regression, run the existing `browser-smoke.mjs` with `SIGNRELAY_V2_STATIC_PREVIEW=1`, `SIGNRELAY_V2_CAMERA_EXPECT=PLEASE`, `SIGNRELAY_V2_EXPECT=PLEASE`, and `SIGNRELAY_V2_SCORE_TRIAL=1`. This tests the generated files and Vercel response headers on loopback. Set `SIGNRELAY_V2_PREVIEW_ORIGIN` to exercise an accessible HTTPS deployment with the same local fixture. Follow the [trial protocol](WEBCAM-TRIALS.md) for labeled webcam sessions. The tested corpus and raw footage remain local.
